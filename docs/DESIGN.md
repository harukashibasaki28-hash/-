## 0. 全体像

```
 ┌──────────── スマホ / PC ────────────┐            ┌────────── Google（自分のアカウント）──────────┐
 │  手帳アプリ（PWA, GitHub Pages）     │            │  GAS Web アプリ（自分として実行）               │
 │   ├ 画面                             │  HTTPS     │   ├ sync: 変更の受け取り・差分の返却             │
 │   ├ 計算（睡眠・繰越・タイムライン） │ ─────────▶ │   ├ calendar: タスク時刻を登録・更新            │
 │   ├ IndexedDB（控え＋未送信の変更）  │ ◀───────── │   └ 合言葉（キー）で本人確認                    │
 │   └ 同期エンジン                     │            │  スプレッドシート「手帳DB」（データの本体）      │
 └──────────────────────────────────────┘            │  時間トリガー: 21:50 翌日To Do / Gmail / 23:00  │
                                                     │  Googleカレンダー・Gmail                        │
                                                     └─────────────────────────────────────────────────┘
```

| 項目 | 決定 |
|---|---|
| 形態 | PWA（ホーム画面に追加）＋PC ブラウザ。GitHub Pages で無料公開 |
| 技術 | ビルド不要の素の JavaScript（ES Modules）＋HTML＋CSS。外部パッケージなし |
| データ本体 | Google スプレッドシート（GAS 経由で読み書き） |
| 端末内 | IndexedDB に控え＋未送信の変更。オフラインでも記録でき、つながったら自動で反映 |
| テスト | Node.js 標準の `node --test`（インストール不要） |
| 有料サービス | なし |

計算ロジックは画面から切り離した関数にして、Node でテストします。

### 1.1 アプリと GAS で計算を共有する
21:50 の GAS も「学習の次の分」「毎日のタスク」「繰越の ID」を作るため、アプリと同じ計算が必要です。
同じ処理を 2 か所に書くと食い違うので、`src/core` の該当ファイル（study / tasks / dates / carryover の ID 規則）は
**ほかのファイルに依存しない純粋な関数だけ** で書き、`tools/build-gas.mjs` が GAS 用に変換して `dist/gas/Code.gs` に同梱します。
あなたが貼り付けるのは `Code.gs` 1 ファイルと `appsscript.json` だけです。

## 2. データ構造

### 2.1 アプリ内・JSON の形（今の形を引き継ぐ）

```jsonc
{
  "days": {
    "2026-11-22": {
      "tasks": [{ "id", "title", "done", "doneAt", "priority", "est", "actualMin",
                  "sessions": [{ "start", "end", "min" }],
                  "runningSince", "deadline", "start", "carryCount", "carriedFrom" }],
      "sleep": { "bed", "wake", "min" },
      "naps": [{ "start", "end", "min" }],
      "note", "closed", "planned", "done", "rate", "review"
    }
  },
  "hourensou": { "<id>": { "to", "what", "kind", "due", "done" } },
  "settings": {...}, "fixedEvents": [...], "templates": [...],
  "subjects": [...], "rules": [...], "inbox": [...]
}
```
- タスクに任意で追加する項目（無くても動く）: `tag`（min / A / 任意、タイトルの【】から自動判定）, `templateId`, `subjectId`＋`unitKey`（学習科目のどの単位か）, `source`（template/study/plan/calendar/gmail）, `calendarEventId`, `updatedAt`。
- **読み込みで受け付ける形**: ①上の形 ②今のチャットのキー形式 `{"days/2026-11-22": {...}, "hourensou/abc": {...}}` ③一部分だけ。読み込み前に件数をプレビューし、「マージ」か「置き換え」を選ぶ。読み込んだデータは同期でスプレッドシートにも入る。
- 日時は `+09:00` 付き ISO 文字列、予定開始などは `"HH:MM"`。
- 夜の睡眠は**起床した日**、昼寝は**開始した日**。「寝る」の時点では「睡眠中」として一時保存し、「起きた」で起床日に確定。

### 2.2 スプレッドシート「手帳DB」のシート

操作はすべてアプリで行い、保存はアプリ（GAS）が自動で行います。直接編集はしない前提ですが、トラブル時に中身を確かめられるよう 1 件 1 行で保存します。

| シート | 1行 = | 主な列 |
|---|---|---|
| `days` | 1日 | date, bed, wake, sleepMin, naps(JSON), note, closed, planned, done, rate, review |
| `tasks` | 1タスク | id, date, title, done, doneAt, priority, est, actualMin, sessions(JSON), runningSince, deadline, start, carryCount, carriedFrom, tag, templateId, source, calendarEventId |
| `hourensou` | 1件 | id, to, what, kind, due, done |
| `templates` | 毎日のタスク1つ | id, title, est, priority, tag, weekdays, order, active |
| `subjects` | 学習科目1つ | id, name, status, tag, examDate, targetDate, structure(JSON), perDay, est, milestones(JSON), position(JSON), startedAt, finishedAt |
| `config` | 1設定 | key（settings / fixedEvents / rules / state）, value(JSON) |
| `inbox` | 1メール | id, from, subject, date, snippet, dateCandidates(JSON), status（new/task/ignored）, link |
| （別ファイル）学習計画 | 1行 | date, subject, content, est … 既存のものがあれば列の対応を設定画面で指定（要確認）。こちらはあなたが編集するので保護しない |

全シート共通の管理列: `rev`（版番号）, `updatedAt`, `deviceId`, `deleted`（削除は印だけ付ける）。

### 2.3 同期のしくみ（sync.js ⇔ Sync.gs）

1. アプリでの変更はすべて、まず IndexedDB に保存し、「未送信キュー」に積む（オフラインでもここまでは動く）。
2. 送るタイミング: 変更の2秒後、アプリを開いたとき、オンラインに戻ったとき、開いている間は5分ごと。
3. 送信 `POST {action:"sync", since:<前回受け取った版>, changes:[...]}`。
   GAS は排他ロック（LockService）を取り、各行に新しい `rev` を付けて保存し、`since` 以降の変更を返す。
4. **競合**: 1件（1日・1タスク・1報連相・1設定）ごとに `updatedAt` が新しい方を採用する。スマホと PC で同じタスクを同時に編集した場合だけ後勝ちになる。
5. **二重作成を防ぐ ID**: 繰越・毎日のタスク・翌日 To Do は**決まった規則で ID を作る**（例: 繰越 `元ID>2026-11-23`、毎日のタスク `tpl:nikkei:2026-11-23`、学習 `stu:fp2:第2章-Sec3`）。スマホと PC の両方で繰越が走っても同じ行になり、重複しない。
6. 画面に「未送信 N 件／最終同期 21:05」を表示。失敗したら自動で再試行。

### 2.4 本人確認（自分以外が読み書きできないようにする）

- スプレッドシート自体は共有しない（自分だけ）。GAS は「自分として実行」。
- GAS Web アプリは、ブラウザアプリから呼ぶために公開範囲を「全員」にする必要がある（「自分のみ」にすると、Safari などで Google のログイン状態を渡せずアプリから呼べない）。
- そこで **合言葉（キー）で本人確認** する:
  - 初回セットアップで GAS が 256 ビットの乱数キーを発行し、スクリプトのプロパティ（自分しか見られない場所）に保存。
  - アプリの設定画面に URL とキーを貼る（PC で表示した QR コードをスマホで読む方法も用意）。キーは端末内にだけ保存し、GitHub には置かない。
  - キーが違うリクエストには何も返さない。失敗が続いたら一時的に拒否。
  - 端末をなくしたときは、GAS でキーを作り直せば古いキーは使えなくなる。
- より強くしたい場合のオプション: Google ログイン（無料の OAuth クライアント ID）で「自分のメールアドレスか」を GAS で確認する。ただし iPhone のホーム画面アプリではログイン画面の挙動が不安定なため、初期は合言葉方式を提案します。

### 2.5 スプレッドシートの保護
- 初回セットアップ（`setup()`）で「手帳DB」の全シートに保護をかけます。
- Google の仕様で、**持ち主（あなた）を編集者から外すことはできない** ため、保護の種類は「**編集しようとすると警告を表示**」にします。誤ってセルを書き換えようとすると「このセルは保護されています」と確認が出て、キャンセルすれば変わりません。
- GAS は「あなたとして」動くので、アプリからの自動保存は保護の影響を受けません。
- 各シートの 1 行目に「このシートはアプリが管理しています。直接編集しないでください」と表示し、シートの色も変えます。
- 誤って書き換えても、スプレッドシートの「変更履歴」から戻せます（手順書に記載）。

## 4. 機能ごとの設計

### 4.1 睡眠ボタン
- 「寝る」「起きた」「昼寝する」「昼寝から起きた」。状態に応じて押せるボタンだけ有効。
- 睡眠時間は 終了−開始（日付またぎ対応）。時刻の修正も可。
- 「寝る」「昼寝する」を押したとき、計測中のタスクがあれば「止めますか？（今止める／そのまま）」と確認。

### 4.2 通知とアラーム（PWA の制約への対応）
PWA は**アプリを閉じている間、指定時刻に確実に通知を鳴らせない**（iPhone は有料のプッシュサーバーが必要、Android も時刻指定通知は未対応）。そのため次のように分けます。

| 用途 | 方法 |
|---|---|
| 起床 6:00 / 昼寝 20 分後 | **iPhone**: ボタンを押すとショートカット「手帳アラーム」が起動し、端末の時計アプリにアラームを作成。**Android/PC**: アラーム付き .ics を開いてカレンダーに追加 |
| 23:00 【min】未完了の一覧 | GAS が 23:00 にスプレッドシートを確認し、未完了があれば**一覧をメールで自分に送る**（Gmail アプリの通知で届く）。アプリを開けば画面上部にも表示 |
| 23:30 寝る準備 | GAS が Google カレンダーに毎日の「寝る準備」予定（通知付き）を登録 → カレンダーの通知で確実に鳴る |
| タイマー 2 時間超 | アプリを開いている間は通知＋確認。閉じていた場合は次に開いたとき確認（「2時間で止める／実際の時刻で止める／続ける」） |

### 4.3 タスクと計測
- 追加・編集・削除・完了。【min】【A】はタイトルから自動判定。
- 開始で `runningSince`、停止で `sessions` に追加して `actualMin` を合計。同時に動くのは 1 つだけ。
- `runningSince` は同期されるので、スマホで開始して PC で止めることもできる。

### 4.4 繰越（carryover.js）
アプリを開いたとき（論理日付が変わっていれば）:
1. 今日より前で `closed=false` の日を全部探す。
2. 未完了タスクを今日へコピー（ID は規則で作成、`carryCount+1`、`carriedFrom=元の日付`、計測はリセット）。
3. その日の `planned / done / rate` を確定して `closed=true`。
4. 今日の毎日のタスク（templates）と学習科目の今日の分（4.5）を追加。繰越分と重複させない。
- 日付の切り替えは **0:00**（確定）。設定で変更可能にはしておく。
- 21:50 の GAS が先に翌日のタスクを作っていても、ID が同じなので重複しない。

### 4.5 学習の自動進行（study.js）

**科目の持つ情報**（画面の「学習」タブで追加・編集・終了）

| 項目 | 例（FP2級） | 例（4002） |
|---|---|---|
| 名前 | FP2級 | ビジネス英単語4002 |
| 区切り方 | 外側=章、内側=Sec（章ごとに Sec 数を指定） | 外側=stage、内側=前半/後半 |
| 全体の量 | 章ごとの Sec 数の合計 | stage 数 × 2 |
| 1日の量 | 1 Sec | 1（＝半 stage） |
| 1単位の見積 | 45 分 | 30 分 |
| 試験日・目標日 | 2027-01-24 | なし（設定すれば警告が有効に） |
| 【min】/【A】 | min | min |
| 特別ルール | 章の全 Sec が終わった翌日に「章末問題」75 分 | なし |
| 状態 | 学習中 / 終了 | 学習中 / 終了 |

区切り方は「外側の名前・書式」「内側の名前（番号 or ラベル一覧）」「外側ごとの内側の数」で表すので、
「Part と Unit」「回（1 階層だけ）」など別の教材も画面だけで登録できます。

**単位の並び**：区切り方から全単位を順番に並べた一覧を作ります（例: 第1章-Sec1, 第1章-Sec2, …, [第1章 章末問題], 第2章-Sec1 …）。特別ルールはこの一覧の「区切りの直後」に差し込まれます。

**翌日の To Do の作り方**（アプリの日付切り替え時と 21:50 の GAS の両方で、同じ関数を使用）
1. 学習中の科目ごとに、「次の単位」から 1 日の量だけタスクを作る。
   タイトル例: `FP2級 第2章 Sec3【min】`、`ビジネス英単語4002 stage5 後半【min】`。
2. 前の日の学習タスクが未完了なら、繰越で残るのでそれを今日の分とし、新しい単位は足さない（溜まり過ぎ防止）。
3. 区切りの翌日は特別ルールのタスク（`FP2級 第2章 章末問題【min】` 見積 75 分）を入れる。`replacesDaily: true` ならその日は通常の Sec を入れない（設定で変更可）。
4. タスク ID は `stu:<科目ID>:<単位>` にするので、スマホ・PC・GAS のどこで作っても重複しない。

**進行**：学習タスクを完了にすると、その科目の `position.next` が次の単位に進む。完了を取り消すと戻る。1 日に先の分までやりたいときは「次の単位を今日に追加」ボタン。途中から使い始めるときは、科目の編集画面で「今どこまで終わったか」を選ぶ。

**遅れ警告**：章ごとの期限（`due`）があれば章ごとに、なければ試験日（目標日）に対して
- 残りの単位数（特別ルールのタスクを含む）÷ 1 日の量 ＝ 必要な日数
- 今日から試験日の前日まで（＋設定で「直前の復習日数」を引く）＝ 使える日数
- 必要な日数 ＞ 使える日数 なら「遅れ: あと N 単位。1日 X 単位のペースが必要」と今日画面と学習画面に表示。余裕がある場合も「予定より N 日先行」と表示。
- オプション「1日の量を期限から自動計算」: 次の章の期限までの残り単位 ÷ 残りの学習日（切り上げ）を、その日の量にする。

**終了と記録**：「終了」にすると翌日以降のタスクは作られず、一覧の「終了した科目」に移る。開始日・終了日・終えた単位・合計の実績時間・単位ごとの完了日（タスクの記録から集計）をあとから見返せる。「学習中に戻す」も可能。

### 4.6 タイムライン自動作成（scheduler.js）
1. 起床（または今）〜就寝目標から、固定予定＋前後の移動枠・食事枠を除いた**空き区間**を作る。
2. 空き時間 × 75% までしか置かない（残りはバッファ）。
3. 置く長さ = 見積 × 倍率（そのタスクの過去の実績倍率 → 全体の実績倍率 → 1.3 の順で採用）。
4. 締切が近い → 優先度が高い → 繰越が多い の順。
5. 重いタスク（45 分以上）は午後の区間を優先、軽いもの（20 分以下）は短い隙間を優先。
6. 90 分ごとに 10 分の休憩を入れる。
7. 入らなかったものは「**後ろ倒し候補**」として理由付きで一覧（明日へ／週末へ／削る）。
8. 決めた時刻は `start` に入り、「カレンダーに登録」で Google カレンダーへ（同じ予定は更新、Asia/Tokyo）。

### 4.7 今日の進捗（夜）
睡眠時間、昼寝の回数と合計、完了率、【min】達成数、見積と実績の倍率、予定開始との平均ずれ ＋ ルールによる課題と改善策。振り返りの一言を `review` に保存。

### 4.8 週の振り返り（日曜。いつでも開ける）
平均睡眠時間、就寝時刻の標準偏差（24時またぎに対応）、完了率の推移グラフ（7日）、翌週に変えること 1 つ（重要度が最も高い改善策）。

### 4.9 報連相・日次ログ・確認候補
- 報連相: 期限が近い順（期限切れは赤で最上部）。今日の画面にも期限 3 日以内を表示。
- 日次ログ表: 日付・就寝・起床・睡眠・昼寝・予定数・完了数・メモ。CSV 書き出しも可。
- 確認候補（Gmail）: 件名・差出人・本文の抜粋・締切候補の日付。「タスクにする（締切を選ぶ）」「報連相にする」「無視」を選ぶ。

## 6A. 既存の「学習計画（英語・FP2級）」シートとカレンダーの読み方

確認した内容（Google ドライブの `学習計画（英語・FP2級）`。添付の Excel は過去の全体計画として参照のみ）:

**シート「予定一覧」** — 列: 開始日｜終了日｜時間｜種類｜予定｜進捗｜内容・メモ

| 行の種類 | 例 | 手帳での扱い |
|---|---|---|
| 時刻あり（`19:00〜21:00` など） | 研修、セミナー | その日の**固定予定**（タイムラインで避ける） |
| 終日・1日だけ（締切・試験・判断・やること） | 英語研修 STEP1 修了、FP2級 進捗チェック① | その日のタスク（締切＝その日）。締切・試験は 7 日前から「近い締切」に表示 |
| 終日・期間（開始日〜終了日） | FP2級：タックスプランニング 11/23〜12/06 | 期間中は今日画面に「今の目標」として表示。FP2級の章の期限にも使う |

**シート「毎日の時間割」** — 列: 曜日｜開始｜終了｜内容｜分類｜期間｜休み・メモ
- 曜日（`月〜金`・`水木金`・`月`・`火`・`土日`）、期間（`11/13〜3/12`、年なし→ 11〜12 月は 2026 年、1〜10 月は 2027 年と解釈。設定で変更可）、休み（`休み：11/18、12/18…`）を読み取り、翌日に当てはまる行を取り出す。
- 取り出した行はその日の**時間の枠**になる。枠に結び付いたタスク（下記）があればその時刻に置き、無ければ行そのものをタスクにする（見積＝終了−開始）。
- `vintage／Part7（隔日交互）` は、期間の初日から数えて交互に `vintage` と `Part7` を割り当てる。
- `土日 予備日` はタスクを作らない（平日の未完了が繰越で入る）。

**時間割の枠と、毎日のタスク・学習科目の結び付け**（画面で変更可。初期値）

| 時間割の行 | 結び付けるもの |

| 英語講座（1h） | 毎日のタスク「英語学習1講座【min】」 |
| 英語：金フレ＋ChatGPT英会話 | 「ChatGPT英会話【A】」＋行の残り（金フレ） |

**Google カレンダー**（11/23 の予定で確認）
- 時間割と同じ内容の**繰り返し予定**がすでに入っている → 時間割シートと二重にならないよう、繰り返し予定は「枠」としてだけ使い、タスクは作らない。
- 終日で「予定なし」扱いの予定（`英語【TOEIC期】` など）は今日画面に表示するだけ。
- それ以外の時刻ありの予定 → 固定予定。

**学習計画シートへの書き戻し**（有効）: いまシートには「手帳／カレンダーから自動追加」の行がある。書き戻しを有効にすると、①FP2級の章を終えたら「進捗」を `完了` に、②予定一覧の 1 日だけのタスクを完了したら `完了` にする。シートの他の列は変更しない。
